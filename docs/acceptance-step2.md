# 验收：谜面 + 敲除/标记 + 截面预览

本轮交付四块：**谜面生成与验证**、**表面数字渲染**、**敲除/标记交互与特效**、
**截面预览模式**。谜面算法的细节见 [`puzzle-generation.md`](./puzzle-generation.md)，
本文只列交互/渲染的实现要点与实测结论。

## 一、操作总览

| 操作 | 行为 |
| --- | --- |
| **左键**点方块 | 敲除。非造型方块 → 碎裂消失；造型方块 → **失误**（闪红、记一次、自动标记） |
| **Ctrl/⌘ + 左键** | 标记（涂色）开关。已标记的方块**受保护，敲不掉** |
| **左键拖底部蓝色滑块** | 进入/调整截面模式 |
| **右键拖拽** | 转视角；**滚轮/中键** 缩放（左键完全让给玩法，不存在误触） |
| `Esc` | 恢复完整显示（退出截面） |
| `N` | 生成并载入一个随机谜面 |
| `H` / `M` / `R` | 提示数字 / 音效 / 显示造型解 开关 |
| `1`–`9` | 切换内置关卡 |

URL 参数：`?level=duck`、`?seed=12345`、`?size=6,6,5`、`?debug=1`、`?audit=1`。

## 二、关键设计决策

### 2.1 失误不会让谜面变得无解

敲到造型上的方块时，方块**不会消失**，而是自动被标记（这也是原作的规则）。
这条规则保证任何误操作都无法破坏谜面，失误只体现在计数上。
标记后的方块受保护，也就不会被反复敲错。

### 2.2 三种"看不见"合并成一个判据

方块不可见有两个来源：模型的 `REMOVED` 位、`SliceRange` 的剖切范围。
两者最终都体现为渲染层的 `blockToSlot[block] >= 0`。
提示贴花的位置计算与鼠标拾取都直接读它，因此**不可能出现"看得见却点不到"**
或"切开了但数字没跟着走"这类割裂。

### 2.3 拾取走体素步进，不走 three 的实例拾取

`InstancedMesh.raycast` 是"逐实例 × 逐三角"：1000 方块 × 108 三角 = 每次十万级三角测试，
而悬停高亮需要每帧拾取。方块本来就是规整体素网格，于是改用 3D-DDA
（`src/core/VoxelRaycast.js`）：沿射线一格一格走，复杂度是"穿过的格子数"（几十步），
结果精确，还免费得到"从哪个面进入"。

滑块与方块的优先级用**同量纲距离**比较：射线方向已归一化且 `CELL = 1`，
所以体素步进给出的 `t` 与 `Raycaster` 的 `distance` 可以直接比大小。

### 2.4 点击与拖拽的区分

按下时记下命中的方块与屏幕坐标；抬起时若位移 > 6px，或指针已不在同一方块上，
则不执行任何操作。副作用是"按下后发现敲错了，拖开再松手"成为一个可用的取消手段。

## 三、表面数字渲染

- **一张运行时生成的字形图集**（`HintAtlas.js`，Canvas2D，16 个数字 × 3 种记号 = 48 格，
  8×6 布局、单格 128px）。零外部资源，改主题色不用重做图集（图集只画白色字形，墨色在材质里 tint）。
- **一个 InstancedMesh** 画全部贴花（`HintRenderer.js`）：几何体是单位平面，
  靠实例矩阵摆到对应方块的对应面，靠**每实例 UV 偏移**从图集取对应格 → **1 个 draw call**。
- 材质用 `MeshBasicMaterial` + `onBeforeCompile` 注入两个实例属性
  （`aCellUv` 图集格原点、`aShade` 该面墨色明度系数），而不是从零写 `ShaderMaterial`：
  这样色彩空间转换与 tone mapping 仍走 three 内置管线，不会出现"数字和场景不在同一色彩空间"。
- 遮挡靠深度测试自然解决：贴花只生成在**朝外无遮挡**的面上，
  被别的方块挡住时会被方块的深度值剔掉。因此 `depthTest: true` + `depthWrite: false`
  + `alphaTest: 0.05` 是正确组合。
- 贴花只在**可见集合变化**后重算（`PuzzleRenderer.visibilityVersion` 版本号比较）。
  纯涂色不会触发重算。

## 四、碎裂与反馈特效

碎裂（`ShardBurst.js`）的"清脆"是五个决定共同作用的结果：

1. **零跳变起手**：方块被敲掉的瞬间换成 2×2×2 八块半尺寸碎片，出生位置正是八个子立方体中心，
   第一帧与原方块严丝合缝 —— 看起来是"裂开"，不是"消失 + 冒粒子"。
2. **快**：全程 0.34s。拖长了就变成"融化"。
3. **沿对角线炸开** + 随机扰动 + 向上初速，配合重力，落势自然。
4. **1 - t³ 收缩**：前段几乎保持原大小（看得清是"块"），末段迅速收没。
5. **随机轴自转**：破坏八块整齐飞出的机械感。

碎片共用方块材质（材质表现完全一致）+ 一个 InstancedMesh（+1 draw call），
0.34s 的寿命不值得进 shadow pass，故关闭投影。

其他反馈：

| 事件 | 视觉 | 听觉 |
| --- | --- | --- |
| 正确凿除 | 碎裂 | 带通噪声冲击（2.6–4.2kHz，4ms 攻击）+ 快速下滑三角波 |
| 失误 | 方块闪红 + 缩放脉冲（`(1-t)·(0.5+0.5cos4πt)`，读起来就是两下"错了"） | 210→78Hz 锯齿闷响 + 低频噪声 |
| 敲到受保护方块 | 冷调蓝闪 | 330Hz 短促木质"哒" |
| 标记 / 取消 | 琥珀色 / 复原 | 上扬 / 下行正弦 blip |
| 拖动截面 | — | 极轻高通噪声（45ms 节流） |
| 通关 | 复位截面 + 横幅 | 四音琶音 |

音效全部 **WebAudio 实时合成**（`src/audio/SoundKit.js`），零资源文件。
每次触发做微小随机化（音高/带宽/衰减），连续敲十几下不会变成机关枪复读。
主总线带限幅器防削波；`AudioContext` 在第一次 `pointerdown` 里解锁。

## 五、截面预览模式

### 5.1 交互形态

沿 **X 轴和 Z 轴各一根导轨，每根两个滑块**（低端 / 高端）。拖任一滑块即进入截面模式：
该轴可见范围被收窄，平面另一侧的方块隐藏。两个滑块可以夹成**一层薄片**——
这是查看内部最有效的姿势，也是把范围而不是单平面作为抽象的原因
（单平面只能从一侧剥，看不到夹在中间的层；区间是单平面的超集，交互上仍是"拖一个条"）。

`SliceRange`（`src/puzzle/SliceRange.js`）就是"每个轴的可见闭区间 `[lo, hi]`"，
两端不允许越过对方，始终保留至少一层可见。

### 5.2 导轨跟着相机换边

导轨固定在长方体底部的棱上。若写死在"前边"，玩家把视角转到背面后手柄就被造型挡住。
因此每帧根据相机所在象限，把 X 导轨放到 z 的近侧、Z 导轨放到 x 的近侧，
手柄永远在离相机最近的两条底棱上。换边会破坏拖动映射，所以**拖动过程中冻结换边**，
并加 0.45 的滞回阈值避免在 z≈0 时抖动。

### 5.3 坐标映射

```
低端滑块在 lo 时，世界坐标 = (lo - N/2) · CELL          // 站在 lo 这一层的外侧面上
高端滑块在 hi 时，世界坐标 = (hi - N/2 + 1) · CELL
```

拖动时用 `Ray.distanceSqToSegment` 求指针射线到导轨线段的最近点，
取其沿轴分量再套上式的反函数即得目标层号（线段自带夹取，越界自然被 `SliceRange` 兜住）。

### 5.4 视觉与可玩性

- 半透明**剖切面**（只在该端被收窄时显示）+ 完整体积**轮廓线**，
  让玩家清楚"切掉了多少、原本有多大"。
- 底部**截面条**显示当前范围（如 `截面模式：X 3–7`）并提供「恢复完整显示（Esc）」按钮。
- 截面里**照常可以敲、可以标记**：拾取用的可见性判据与渲染完全一致。
- **数字实时迁移**：新暴露的截面上立刻长出该轴的提示数字（实测见下）。
- 通关时自动复位截面，把完整造型露出来再放庆祝。

### 5.5 剖切时的可见集合重建

拖动截面一次会隐藏/恢复成百上千个方块，逐个走"尾部交换"反而更慢也更绕；
直接按整数坐标顺序 O(N) 重填一遍槽位，既简单又保证槽位顺序稳定（截图可复现）。

## 六、实测数据

浏览器：Chromium（Playwright 驱动），1080×675 视口，`devicePixelRatio` 上限 2。
复现方式：

```bash
npm run dev
playwright-cli goto "http://localhost:5173/?level=duck"
playwright-cli --raw run-code --filename=tools/browser-check.js
```

`tools/browser-check.js` 覆盖下面除 §6.1 离线部分之外的全部条目；
离线部分用 `npm run audit:levels` / `test:generator` / `test:repair`。

### 6.1 谜面与提示

| 项 | 实测 |
| --- | --- |
| 内置关卡校验 | **7/7 唯一解且无需猜测**，单关 0.1–1.3ms |
| 随机谜面（离线 40 个） | **40/40 落在「3 适中」**（2.86–3.23），平均 1ms、最慢 5ms，兜底 0 次 |
| 随机谜面（浏览器连开 6 局） | 全部 `ok = true`，含换关过场每局 124–177ms |
| 提示贴花容量 | duck 8×8×4 上界 256、实际 190；stress-10 上界 600、实际 440；**溢出 0** |
| 提示随凿除迁移 | duck 全量凿除后仍是 190 个贴花，全部落在造型表面（见 `screenshots/14`） |

### 6.2 截面模式

| 步骤 | 实例数 | 贴花数 | 状态文案 |
| --- | --- | --- | --- |
| 初始（8×8×4） | 256 | 190 | 完整显示 |
| X 低端拖到 3 | 160 | 150 | X 3–7 |
| 再把高端拉到 4（薄片） | 64 | 104 | X 3–4 |
| `Esc` 恢复 | 256 | 190 | 完整显示 |

- 实例数与理论值一致（`X 3–7` → 5×8×4 = 160；`X 3–4` → 2×8×4 = 64）。
- 新暴露的 `x = 3` 截面上出现 **28 个朝 -X 的数字贴花**（见 `screenshots/13`）。
- **真实鼠标**（不是脚本直接改状态）拖动滑块：悬停命中 `SliceKnob_X_lo`，
  拖动后进入 `X 3–7`，底部截面条出现；`Esc` 后完整恢复。

### 6.3 交互与状态机

| 用例 | 结果 |
| --- | --- |
| 敲除非造型方块 | 实例 256→255，碎片 8 片，失误 0 |
| 敲到造型方块 | 失误 +1，方块**仍在场**，**自动标记**，实例数不变 |
| 再敲同一块（已标记） | 仍在场，失误**不再增加**（保护生效） |
| Ctrl+左键 | 标记 / 取消标记均生效 |
| 截面里真实点击 | 敲除、Ctrl 标记均生效 |
| 悬停高亮 | 命中方块，实例色 ×1.2，指针变 `pointer`；命中滑块变 `grab` |
| 全量凿除 | `solved = true`，实例数 118 = 解方块数，槽位双向映射 mismatch **0** |
| 通关 | 自动复位截面 + 横幅出现 + 琶音 |

### 6.4 性能

| 场景 | 结果 |
| --- | --- |
| stress-10（10³）静态 | **60 FPS**，1000 实例 / 108,000 三角 / 440 贴花 / **2 draw call** |
| stress-10 每帧改一次截面 | **60 FPS** |
| 单次"重建可见 + 重算提示"（1000 格） | 平均 **1.61ms**，最慢 12.8ms（首次含预热） |
| 控制台 | 0 错误 0 警告 |

## 八、边界

本轮**没有**实现：计时与限时、失误上限/失败判定、连续拖拽多格凿除、
关卡进度存档、教学引导、移动端触屏专用手势。
数据层已为这些留好位置（`PuzzleModel.getStats()` 已含 `mistakes`/`progress`/`solved`，
`LevelSchema` 预留了 `timeLimit`/`initialStates`）。
