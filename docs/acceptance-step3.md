# 验收：提示裁剪 · 整行上色 · 通关演出 · 反馈修复

本轮交付：**提示整行隐藏（含 0 的显式显示）**、**关卡最终配色 + 冷知识**、
**整行完成的描边与上色**、**通关环绕演出**，以及六条验收反馈的修复。
谜面算法细节见 [`puzzle-generation.md`](./puzzle-generation.md)，
上一轮的交互/渲染基础见 [`acceptance-step2.md`](./acceptance-step2.md)。

## 一、提示：0 要显示，冗余的整行藏掉

原来"没有数字"表示这条线要全凿掉，于是空白面既可能是 0、也可能是别的原因，
玩家凿开一块后看到空白面会以为渲染漏了。现在改成：

```
数字（含 0） → 这条线的信息已知
空白         → 这条线的提示被故意隐藏，得靠另两个轴推出来
```

隐藏由 `PuzzleSolver.pruneHints` 离线算出：候选顺序按关卡 id 作种子确定性打乱，
每藏一条就重跑传播验证"仍能全部推出"，并在难度超过 3.9 时撤回。
结果写进关卡 JSON 的 `hiddenHints`，运行时零成本导入；**隐藏的线不参与求解**。

| 关卡 | 裁剪前难度 | 裁剪后难度 | 隐藏 / 全部 | 可见提示（数字 + 0） |
| --- | --- | --- | --- | --- |
| tutorial-cube | 1.72 轻松 | 1.72 轻松 | 13 / 27 | 6 + 8 |
| stress-10 | 1.90 轻松 | **2.37** 轻松 | 125 / 300 | 125 + 50 |
| mushroom | 1.79 轻松 | **2.75** 适中 | 33 / 75 | 28 + 14 |
| heart | 2.36 轻松 | **2.78** 适中 | 40 / 81 | 27 + 14 |
| house | 2.55 适中 | **3.06** 适中 | 30 / 75 | 25 + 7 |
| mug | 2.47 轻松 | **3.37** 适中 | 39 / 84 | 38 + 7 |
| duck | 2.61 适中 | **3.65** 有挑战 | 63 / 128 | 55 + 10 |

七关**全部仍是"唯一解 + 无需猜测"**。裁剪耗时 0 ~ 14ms（离线）。

字形图集相应扩到 0..16 × 3 种记号 = 51 格；0 按 80% 字号绘制，
让它在视觉上退后一档，不跟造型抢注意力。

## 二、最终配色与冷知识

关卡 JSON 新增三个字段：

```jsonc
"palette": ["#ffd447", "#ff8c26", "#2b2b31"],   // 最多 9 色
"colors":  [ /* 与 layers 同形，字符 1..9 索引 palette，'.' 等于第一个颜色 */ ],
"trivia":  "小黄鸭最早是实心橡胶做的…"            // 通关时显示在屏幕正下方
```

- 省略 `colors` 时按**高度均分调色板**兜底：单色关卡直接一片纯色，
  多色关卡自然形成自下而上的分层渐变（`stress-10` 就靠这个拿到 5 色渐变塔）。
- `'.'` 等价于第一个颜色，所以"整层都是主色"的图层可以直接写一片点，
  只有换色的格子写数字——手写模板时省下大量噪音。

### 2.1 为了让配色准确，材质本色改成纯白

最终画面色 = 材质色 × 实例色。原来材质本色是象牙 `#f3ede1`，
那么把实例色设成关卡配色时会被象牙"染"一遍，颜色不准。
现在材质是纯白，象牙色移进"未处理"的默认实例色，
配色上身即为准确值（实测确认块实例色 = `#7fc4ff` 的线性值，误差 0）。

### 2.2 三种状态必须一眼可辨

| 状态 | 颜色 | 为什么是这个颜色 |
| --- | --- | --- |
| 未处理 | `#ded8cb` 略沉的石膏白 | 比任何偏白的关卡配色**暗一档** |
| 已标记 | `#f0a94b` 饱和橙琥珀 | 没有关卡用它作主色，绝不会和最终配色混 |
| 已确认 | 关卡配色 | 亮起来即"锁定" |

这两条都是踩坑改出来的：最初标记色是浅琥珀 `#ffd7a3`，和小屋的墙色几乎一样；
把未处理压暗之前，"瓷白杯身 / 白菌柄 / 白墙"这类偏白配色跟未处理块也分不出来
（ACES tone mapping 会把两个都压到接近纯白）。

## 三、整行完成 → 描边 → 上色锁定

一条线"做完"的定义：**这条线上该凿的都凿了、该留的都涂了，且线上确实有方块**。
此时线上的方块进入 `CONFIRMED`：显示最终配色并**锁定**（不能取消标记、不能敲掉）。

反馈是两层叠加：

1. **描边**（`LineHighlight`）：沿这条线画一个发亮线框，从中间 `easeOutBack` 弹开到全长，
   随后整体略微外扩并淡出，共 0.62s。用线框而不是发光实体，是因为紧接着就要
   在同一位置上色——不透明实体会把上色过程整个盖住。线框 `depthTest: false`，
   保证被别的方块挡住时也看得见。
2. **上色**：这一行的方块按线上顺序、每格延迟 45ms 亮起白光，曲线是
   "18% 时间升满 → 保持到 60% → 落回常态色"。**保持段**就是给描边留的时间，
   颜色在描边尾声才浮出来，而不是"啪"一下换色。

确认会**连锁**：一个方块被确认（等于被涂上）可能让穿过它的另两条线也刚好凑满。
`PuzzleModel` 用显式工作队列处理连锁，连锁再长也不会爆栈；
音效按同时完成的行数整体升调（半音 ×2 一档，最多 4 档），连着响不会糊成一团。

O(1) 判定靠构造时预算好的两个计数器：每条线「还差几个要凿」「还差几个要涂」，
之后只做加减。

## 四、通关演出

1. **全模型上色**：还没被"整行完成"覆盖到的方块一次性确认，
   按 y 自下而上每层延迟 20ms，形成"从脚下往上填色"的一道波。
2. **环绕推进镜头**（`VictoryCinematic`）：把相机位置转成以造型中心为原点的球坐标，
   只对三个分量插值 —— 方位角连续转满 360°、极角缓动到 72° 的展示角、
   半径缩到 78%（推进），7 秒走完，之后转为很慢的匀速待机旋转。
   这样**无论玩家从哪个视角通关，起手都是平滑的**，不会硬切到预设机位。
3. **顶部模型名 + 底部冷知识**：标题在屏幕正上方，冷知识卡片在正下方；
   操作面板淡到 16% 让出画面，表面数字与拖动条一并收起（造型要干净）。
   `Esc` 或点「结束展示」把镜头与操作交还玩家。

表面数字用 `setSuppressed` 而不是 `setEnabled` 收起，
这样演出结束后恢复的是玩家原本的开关选择，而不是"演出前刚好可见"。

## 五、六条验收反馈

| # | 反馈 | 处理 |
| --- | --- | --- |
| 1 | 不要有投影 | 关闭 `shadowMap`、移除接影地面与所有 `castShadow`；环境光强度 0.5→0.62、补光 0.35→0.5、顶光 0.35→0.45 把体积感补回来。副作用是省掉每帧一次 shadow pass |
| 2 | 整行完成要有描边特效，之后展示最终颜色 | 见 §3 |
| 3 | 移除随机关卡 | HUD 按钮、`N` 快捷键、`?seed` 入口、`App.loadRandomLevel` 全部移除；`PuzzleGenerator` / `RandomLevel` 降级为审计工具的内部设施（文件头已注明） |
| 4 | 一整行 0 个也要标出 0 | 见 §1，图集扩到含 0；`collectHintFaces` 改为"按 visible 过滤"而不是"按 count 过滤" |
| 5 | 敲掉方块后被它盖住的面没数字 | 根因就是 #4：那些面对应的线正好是 0，旧逻辑什么都不贴。实测确认修复（见 §6.2） |
| 6 | 进入一个轴的截面后隐藏另一个轴的拖动条 | `SliceRange.activeAxis` / `canSlice()` 在数据层拒绝另一轴；`SliceHandles` 把另一轴的导轨、滑块、剖切面整组隐藏，且 `interactiveObjects` 只返回**可见**滑块（否则会出现"拖一个看不见的东西"） |

另外把工具写回 JSON 的格式修好了：纯量数组压成一行、`layers` 每层一行，
一个 5³ 关卡从 140 行回到 39 行，仍然是可读可 diff 的资产。
顺手用内联 SVG 图标消掉了控制台常驻的 `favicon.ico` 404。

### 6.2 凿除后新暴露面立刻长出数字（反馈 #5）

在 `+X` 外壳上取一个提示可见的非解方块，凿掉它：

| | 该方块的 +X 面有贴花 | 它背后那块的 +X 面有贴花 |
| --- | --- | --- |
| 凿除前 | ✓ | ✗ |
| 凿除后 | ✗ | **✓** |

样本所在线的 `count = 0` —— 正好印证了根因：旧逻辑不贴 0，所以那个面永远空白。
