# 谜面：规则、可解性验证与生成

本文回答四件事：提示数字**怎么算**、谜面**能不能算法生成**、怎么**证明它不需要猜**、
难度**怎么量化**。实现全在 `src/puzzle/`，纯数据、不依赖 three，Node 可直接跑。

## 1. 调研结论

参考实现与资料：

| 来源 | 结论 |
| --- | --- |
| `nathsou/Picross3D`（TS，浏览器版） | 有**求解器**、手工**编辑器**、`.OBJ 模型 → 体素 → 谜面`转换器；**没有随机生成器** |
| `epmjohnston/Picross-3D-Solver` | 求解器；确认圆圈 = 恰好 2 段的语义 |
| Picross Wiki / 原作规则 | 数字 = 该线方块总数；圆圈 = 恰好 2 段；方框 = ≥3 段 |

关键结论：**提示是造型的函数**。

```
computeHints(grid, solution) → hints        // 确定性映射，没有任何随机自由度
```

所以"给同一个关卡换一套不同的谜面"在规则层面不存在——一个造型只对应一套提示。
能随机的只有**造型本身**。因此项目采取双轨：

1. **内置美术关卡**：造型人为设定（小鸭子 / 马克杯 / 心形 / 小屋 / 小蘑菇…），
   提示自动推导，再用求解器审计；不合格的用最小改动修复（见 §5）。
2. **随机关卡**：算法生成造型，**生成即验证**，只产出"唯一解 + 全程无需猜测 +
   难度落在目标区间"的谜面。点 HUD 的「随机谜面（N）」或访问 `?seed=12345` 即可。

## 2. 提示规则（`src/puzzle/HintModel.js`）

沿 X / Y / Z 三轴，每条"线"（另两轴坐标固定）都有一个提示：

| 记号 | 语义 |
| --- | --- |
| 裸数字 `4` | 该线共 4 个方块属于造型，且**连成 1 段** |
| 圆圈 `④` | 该线共 4 个方块，**恰好分 2 段** |
| 方框 `▣4` | 该线共 4 个方块，**分 3 段或更多** |
| `0` | 这条线**整条都要凿掉** |
| **空白** | 这条线的提示被**故意隐藏**了（见 §2.1） |

数字表示的是**该线的总数，恒定不变**，不随凿除减少；变的只是它印在哪一块上（见 §6）。

### 2.1 显式显示 0，把空白让给"隐藏"

原作用"没有数字"表示 0。本项目改成**显式画出 0**，是为了给"整行隐藏提示"腾出语义空间：

```
看到数字（含 0） → 这条线的信息已知
看到空白         → 这条线的提示被藏起来了，得靠另两个轴推出来
```

这一条不只是美术选择，它直接解决了一个真实的体验问题：
凿掉一个方块后，后面那块露出来的面如果什么都没有，玩家会以为渲染漏了；
现在只要那条线不是被隐藏的，露出来的面上一定有数字（哪怕是 0）。

### 2.2 为什么要隐藏一部分提示

1. **画面干净**：每条线都印数字时六个面密密麻麻，造型本身被淹没。
2. **提升难度**：少一条已知条件，玩家就得绕道另两个轴。

三轴提示对小网格是**高度过约束**的（N³ 个格子对应 3N² 条线），很多线是冗余的。
判断"能不能藏"没有捷径：藏掉之后重跑一遍传播，只要仍能把每一格都定下来，就说明它冗余。

`PuzzleSolver.pruneHints` 做的就是这件事：

- 候选顺序按**关卡 id 作种子**确定性打乱 —— 隐藏分布看起来自然（不成条带），
  同时同一关每次算出来完全一样，可复现、可 diff。
- 每次成功隐藏后重新评分，一旦超过 `maxScore`（默认 3.9）就撤回这一步。
  这是"有挑战但不太难"的直接闸门。
- `maxHiddenRatio`（默认 50%）是兜底，避免画面被藏得太空。

结果写进关卡 JSON 的 `hiddenHints` 字段（`npm run prune:levels`），运行时零成本导入。
**被隐藏的线不参与求解**——它对玩家不可见，就不该被算作已知条件
（`solveByPropagation` 在入队时就把它们滤掉了）。

线的编号与 `GridCoords.lineOf` 一致：`axis=X → (u,v)=(y,z)`、`axis=Y → (x,z)`、
`axis=Z → (x,y)`，同轴内 `key = u + v * uCount`。提示用四组平行 `Uint8Array`
存储（counts / groups / marks / visible），16³ 谜面总共 768 条线、不到 1KB。

## 3. 可解性验证（`src/puzzle/PuzzleSolver.js`）

### 3.1 "不需要猜"的定义

坏谜面有两种：**多解**（提示无法唯一确定造型）和**唯一解但要试错**
（必须假设某格、往下推、矛盾了再回退）。本项目把合格定义为：

> 只用**逐线约束传播**，就能把每一格都定下来。

### 3.2 逐线约束传播

一条长度 L 的线，"哪些格子保留"可以用 L 位整数位掩码表示。给定提示 `(count, mark)`，
合法掩码集合是**固定的**（与谜面无关），因此按 `(L, count, mark)` 缓存
（`src/puzzle/LineMasks.js`）：一次枚举 O(2^L)（L ≤ 16 → 最多 65536 次整数运算），
之后每次线求解只是几次位运算。

对每条线：

```
筛掉与已知状态冲突的候选：
    (mask & goneMask) != 0   → 候选要求保留一个已确定凿除的格子
    (keepMask & ~mask) != 0  → 候选要求凿除一个已确定保留的格子
剩余候选取交集：
    allOnes  &= mask         → 所有候选都是 1 的位 ⇒ 该格必须保留
    allZeros &= ~mask        → 所有候选都是 0 的位 ⇒ 该格必须凿除
候选数为 0 ⇒ 矛盾
```

任何一格被定下来，就把穿过它的**另两条线**重新入队（`cellLines` 预计算），
直到不动点。用环形队列 + `inQueue` 去重，队内元素不会超过线总数。

### 3.3 为什么"传播全部定下来"就等于"唯一解且无需猜测"

传播只做**强制**推断（不含任何假设），所以任何合法解都必须与推断一致。
若传播把每一格都定下来且无矛盾，那么合法解至多一个；而给定造型本身是合法解，
故解唯一，且这一串推断本身就是一条不含猜测的解题路径。

传播卡住时才用回溯计数（`countSolutions`，带节点预算）区分"多解"与
"唯一但要试错"，仅用于报告与修复决策；中小谜面（≤600 格）才做，避免卡浏览器。

## 4. 难度模型（`rateDifficulty`）

四个可观测量线性加权（各项归一化到 [0,1]），外加一个反向的"送分度"：

| 指标 | 含义 | 权重 |
| --- | --- | --- |
| `waves` | 传播波次 = 推理链深度（"先推出 A 才能推出 B"的层数） | 1.7 |
| `maxCandidates` | 产生推断时单条线的最大候选数 = 一步内要枚举多少情况 | 1.1 |
| `hardDeductions` | 候选数 > 6 的推断次数占格数比例 | 0.9 |
| `markedRatio` | 圆圈/方框提示在有数字提示中的占比 | 0.8 |
| `1 - firstWaveRatio` | 一眼就能填的格子越少越难 | 0.5 |

`score = 1 + Σ` → 1.00 ~ 6.00，四舍五入成 1..5 级：
**1 入门 / 2 轻松 / 3 适中 / 4 有挑战 / 5 硬核**。

内置关卡实测（均为**裁剪后**，即含隐藏提示的最终形态）：

| 关卡 | 尺寸 | 解 | 难度 | 波次 | 可见提示（裸/圆/方/零） | 隐藏 |
| --- | --- | --- | --- | --- | --- | --- |
| tutorial-cube | 3×3×3 | 8 | 1.72 轻松 | 2 | 6 / 0 / 0 / 8 | 13 / 27 |
| stress-10 | 10×10×10 | 440 | 2.37 轻松 | 3 | 125 / 0 / 0 / 50 | 125 / 300 |
| mushroom | 5×5×5 | 37 | 2.75 适中 | 4 | 28 / 0 / 0 / 14 | 33 / 75 |
| heart | 7×6×3 | 59 | 2.78 适中 | 4 | 27 / 0 / 0 / 14 | 40 / 81 |
| house | 5×5×5 | 67 | 3.06 适中 | 3 | 25 / 13 / 0 / 7 | 30 / 75 |
| mug | 6×6×4 | 88 | 3.37 适中 | 4 | 28 / 8 / 2 / 7 | 39 / 84 |
| duck | 8×8×4 | 118 | 3.65 有挑战 | 5 | 49 / 6 / 0 / 10 | 63 / 128 |

裁剪把难度从 1.72–2.61 抬到 1.72–3.65，同时**七个关卡全部仍是"唯一解 + 无需猜测"**，
单关校验 0.1 ~ 0.9ms，裁剪本身 0 ~ 14ms。

## 5. 最小改动修复（`repairSolution`）

手绘造型若不幸不可解，不应该整张重画。修复思路：

> 传播卡住时剩下的未定格子就是歧义所在。翻转其中一格会改写它所在**三条线**的提示，
> 往往就能把歧义打开。

每一轮在未定格里随机采样若干候选，逐个试翻转、取"未定格数下降最多"的那个落盘
（贪心爬山），允许最多连续 3 轮平台期。因为改动量以"格"为单位且优先最有效的那格，
造型轮廓基本不变。

实测（`node tools/level-audit.mjs --repair 36`，6³ 纯噪声造型、填充率 0.06~0.94 扫描）：

- 3D 提示对小网格是**高度过约束**的（N³ 格对应 3N² 条线），
  中等填充率的噪声造型大多本来就可解；容易出歧义的是极稀疏 / 极稠密的造型。
- 36 个样本里 1 个输入不合格，修复后 36/36 全部可解，需修复样本**平均翻转 1.0 格**（0.5% 格子）。

## 6. 提示贴到哪一块上（`src/puzzle/HintFaces.js`）

提示不是浮空标签，而是**印在方块表面**。一条沿 axis 的线上，找出第一个可见方块 a
与最后一个可见方块 b：a 的负向面、b 的正向面各贴一个该线的提示（a === b 时同一块两侧都贴）。
`visible = 0`（整行隐藏）的线什么都不贴；**数字 0 会照常贴出来**。

"可见"由 `PuzzleRenderer.blockToSlot[block] >= 0` 给出，因此**已凿除**与
**被截面隐藏**两种不可见共用同一套判据——凿掉一块之后，同一条线的数字会立刻
"移"到它后面那块的表面上；切开截面后，新暴露的截面上也会立刻长出该轴的数字。

每条线最多 2 个贴花，于是贴花数有紧上界：`2 × (H·D + W·D + W·H)`。
10³ 谜面只有 600 个，一次性分配、全部塞进一个 InstancedMesh（1 个 draw call）。

## 7. 随机生成（`src/puzzle/PuzzleGenerator.js`，仅开发工具用）

> 游戏本体**已不提供随机关卡模式**，玩法只走内置的美术关卡。
> 生成器保留下来是因为它是 `--gen` / `--fix` 两个冒烟测试的基础设施。

纯随机撒点不行：每条线都被切成很多段，提示满屏方框，又丑又容易要猜。造型生成分四步：

```
团块生长  growBlob        从中心种子沿前沿扩张；前沿采样"三选一取邻居最多者"，长出紧实团块
镜像对称  mirrorX         50% 概率沿 X 镜像，更像"物件"，提示也更规整
形态平滑  smooth          去毛刺（邻居 ≤1 的实心删掉）、填凹坑（六面被围五面的空格填上）
连通筛选  keepLargestComponent   只保留最大 6 连通块，保证是"一个东西"
打孔      carveHoles      在连续且够长的线上掏掉中间 1~2 格 → 制造圆圈提示与内部空腔
```

然后 `分析 → 不合格就 repairSolution → 难度评分`。单次尝试 1~3ms，因此**不取第一个合格的**，
而是跑满预算（默认 28 个造型 / 2.5s），从所有合格候选里挑难度最接近目标
（默认 `targetScore = 3.05`，接受区间 `[2.5, 4.0]`）的一个。
若全军覆没，退回**随机子长方体**——它在规则上一定可解（所有 0 提示线清空后剩下的就是它自己）。

种子化（`src/core/Rng.js`，mulberry32）：同一个 seed 一定生成同一个谜面，
出问题能稳定重现，也方便分享。

实测（`node tools/level-audit.mjs --gen 40`）：

- 难度分布 **40/40 全部落在「3 适中」**（score 2.86 ~ 3.23）
- 平均 1ms、最慢 5ms；兜底子长方体 0 次；平均修复 0.0 格
- 浏览器内连开 6 局（含换关过场动画）每局 124 ~ 177ms，全部 `ok = true`

## 8. 审计工具（`tools/level-audit.mjs`）

```bash
npm run audit:levels        # 审计全部内置关卡，输出可解性与难度报告
npm run prune:levels        # 计算"可以整行隐藏的提示"并写回各关卡的 hiddenHints
npm run audit:levels:fix    # 对不合格关卡做最小改动修复并写回
npm run test:generator      # 冒烟测试随机生成器（成功率 / 耗时 / 难度分布）
npm run test:repair         # 冒烟测试修复算法（纯噪声造型 + 填充率扫描）
```

**改了造型之后一定要重跑 `npm run prune:levels`**：`hiddenHints` 是针对特定造型算出来的，
造型一变就可能失配（藏掉了不该藏的提示 → 谜面变成要猜）。
两道防线会立刻发现失配：`npm run audit:levels` 会标 `✗`；
游戏加载该关时也会 `console.warn` 并在 HUD 上把结论标红。

做成离线工具而不是运行时计算，是因为内置关卡的造型属于**资产**：
修复与裁剪结果应当固化进 JSON 并可 diff 审查，而不是每次启动在浏览器里重算
（裁剪要跑上百次传播）。工具写回时用自定义序列化保持紧凑：
纯量数组压成一行，`layers` 每层一行——一个 5³ 关卡是 39 行而不是 140 行。

前端只保留轻量入口——`?audit=1` 会把全部内置关卡的校验结果 `console.table` 出来。

```

src/puzzle/PuzzleSolver.js    逐线传播、回溯计数、analyzePuzzle、难度评分

tools/level-audit.mjs         离线审计 / 修复 / 冒烟测试
```
